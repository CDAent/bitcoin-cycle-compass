# Architecture Map
## Bitcoin Cycle Compass — Version 8.7 · Sprint 0

---

## 1. Application Overview

Bitcoin Cycle Compass is a **Progressive Web Application (PWA)** delivered as a static site via GitHub Pages. It provides real-time Bitcoin market intelligence by combining price data, macro economics, on-chain metrics, ETF flows, stablecoin liquidity, sentiment, and AI-assisted analysis.

The architecture follows a **two-layer design**:

| Layer | Technology | Execution Environment |
|---|---|---|
| **Data Pipeline** | Python 3.11 scripts | GitHub Actions (server-side, scheduled) |
| **Frontend** | Vanilla HTML/CSS/JS | Browser (client-side) |

There is no traditional web server, no Node.js runtime, and no backend API layer at runtime. All data processing happens at **build/update time** and the result is served as a static JSON file.

## 4. Frontend Architecture

The entire frontend lives in a **single file**: `index.html`. It contains:

- All CSS (inline `<style>` block, ~330 lines)
- All HTML markup
- All JavaScript (inline `<script>` block, ~530 lines of minified logic)

### 4.1 CSS Architecture

CSS is organised in a single inline `<style>` block using:

- **CSS custom properties (design tokens)** in `:root` — all colours, spacing, and radii
- **Semantic class names** — `.card`, `.nav-item`, `.gauge`, `.detail-panel`
- **Grid-based layout** — 12-column dashboard grid via CSS Grid
- **Media queries** — breakpoints at 1180px, 900px, 820px, 760px
- **State classes** — `.pos`, `.neg`, `.neu`, `.active`, `.open`, `.enabled`
- **Version-annotated sections** — CSS blocks are annotated with the version that introduced them

### 4.2 JavaScript Architecture

All JS is in a single inline `<script>` block. Structure:

```

  formatAppDate(), relativeTime(), formatArticleTime()

  movementClass(), movementArrow(), trendInfo()
  scoreLabel(), regimeFromScore(), liquidityShares()

  buildEvidenceRegister(), evidenceQuality(), profileLanguage()
```

## 5. Backend / Data Pipeline Architecture

### 5.1 update_data.py

The primary data orchestrator. Runs in GitHub Actions on a schedule.

```
update_data.py
  ├── price_sources()      → Coinbase, Kraken, Bitstamp, CoinGecko
  ├── fx()                 → Frankfurter API (USD/AUD)
  ├── fear()               → Alternative.me Fear & Greed
  ├── stablecoins()        → DeFiLlama stablecoincharts
  ├── macro()              → FRED (WALCL, M2SL, DGS10, DTWEXBGS, VIXCLS)
  ├── chain()              → Blockchain.info (hash-rate, n-transactions, mempool)
  ├── stooq()              → Stooq (gold, equities, AI proxy prices)
  ├── etf_flow()           → Farside scraper + etf_demand_proxy()
  ├── etf_demand_proxy()   → Yahoo Finance (IBIT, FBTC, ARKB, BITB, GBTC, BTC)
  ├── btc_daily_history_four_years() → Yahoo Finance BTC-USD 4y daily
  ├── weekly_btc_history() → derived from daily (Monday buckets)
  ├── news()               → Google News RSS (3 search queries)
  ├── events()             → hardcoded official calendar links
  ├── article_significance() → rule-based news scoring
  ├── reports_payload()    → summary sections for Reports view
  ├── sync_manifest_versions() → keeps manifest.json version in sync
  ├── save_daily_to_db()   → upserts all tables in history.db
  ├── write_full_snapshot() → upserts market_snapshots row
  └── writes data/live.json
```

### 5.2 SQLite Database (history.db)

The database is created at runtime and is **not committed** to the repository. It exists only in the GitHub Actions environment during CI and in local development.

```
history.db
  ├── schema_version          Migration tracker (current: v2)
  ├── btc_daily               Daily BTC price (USD + AUD)
  ├── fear_greed              Daily sentiment index
  ├── etf_flows               Daily ETF net flows and scores
  ├── stablecoin_market_cap   Daily stablecoin market cap
  ├── scores                  Daily composite scores
  ├── market_regime           Daily regime label and confidence
  ├── capital_allocation      Daily estimated capital allocation %
  ├── market_data             Daily gold, S&P500, NASDAQ, DXY, US10Y
  ├── market_snapshots        V2 unified snapshot (all fields, one row/day)
  └── build_metadata          Key/value build and version metadata
```
